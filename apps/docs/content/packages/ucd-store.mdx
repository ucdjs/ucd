The `@ucdjs/ucd-store` package manages a local cache of Unicode Character Database files. It tracks what has been downloaded via a lockfile, supports mirroring specific versions, and can verify the integrity of local files against the remote API.

## Installation

```package-install
@ucdjs/ucd-store
```

## Overview

A store is a directory on disk containing UCD files organized by version. The store is described by a `ucd.lock` lockfile that records which versions and files are present, along with their hashes. This lets other tools (`@ucdjs/cli`, pipelines) work against a stable, reproducible local snapshot of the UCD.

## Core Operations

| Operation | Description |
|---|---|
| **mirror** | Download UCD files for one or more versions |
| **sync** | Bring the store on disk in line with the lockfile |
| **verify** | Check local files against the remote API |
| **analyze** | Report on the contents and status of the store |
| **status** | Show which versions are present and their state |

<Callout type="info">
  All of these operations are available through the [`ucd store`](/packages/cli/store) CLI commands without writing any code.
</Callout>

## File System Backends

The store works with filesystem-style backends for local disk access, remote HTTP access, and testing-friendly in-memory implementations. In the public docs, the backend model is documented through [`@ucdjs/fs-backend`](/packages/fs-backend).

<Callout type="info">
  If you are building tooling around store-style file access, start with <a href="/packages/fs-backend"><code>@ucdjs/fs-backend</code></a>.
</Callout>

## Lockfile

The `ucd.lock` file is the source of truth for a store. It records:

- Which Unicode versions are tracked
- Which files belong to each version
- A content hash per file for integrity verification

The lockfile is written on `init` and `mirror`, and read by `sync` and `verify` to determine what should be on disk.

## Typical Lifecycle

This is the most common high-level usage flow for a writable store.

```mermaid
sequenceDiagram
  actor App as Consumer app / CLI
  participant Factory as createNodeUCDStore()
  participant Store as UCD Store
  participant API as UCD API
  participant FS as Filesystem backend

  App->>Factory: createNodeUCDStore({ basePath, versions, requireExistingStore: false })
  Factory->>Store: createUCDStore(...)
  Store->>API: discover config + list versions
  Store->>FS: read or create .ucd-store.lock
  Store-->>App: store instance

  App->>Store: mirror({ versions })
  Store->>API: get file tree + fetch files
  Store->>FS: write files + snapshot + lockfile
  Store-->>App: MirrorReport

  App->>Store: files.get(version, path)
  Store->>FS: read local file
  FS-->>Store: file contents
  Store-->>App: { data, error }

  App->>Store: analyze()
  Store->>FS: inspect local files + snapshots
  Store-->>App: AnalysisReport
```

For the method-level execution diagrams, see the
[`ucd-store` architecture notes](/architecture/packages/ucd-store).
