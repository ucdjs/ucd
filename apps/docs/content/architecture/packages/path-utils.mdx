`@ucdjs/path-utils` is the path safety layer that protects storage and HTTP file access.

## Role

- Normalizes path handling across Node, HTTP, and mixed platform environments.
- Rejects traversal, illegal characters, unsupported UNC paths, and Windows-drive mismatches.
- Provides the safety boundary reused by `fs-backend`, `client`, and store-serving code.

## Mental Model

There are two main responsibilities:

- decode and normalize user-provided paths safely
- prove that the resolved path still stays inside an allowed base

The core primitive is `resolveSafePath(basePath, inputPath)`.
Everything else supports that decision.

## Method Flows

### `resolveSafePath(basePath, inputPath)`

```mermaid
sequenceDiagram
  actor Caller
  participant Resolve as resolveSafePath()
  participant Decode as decodePathSafely()
  participant Guards as UNC / illegal char guards
  participant Base as isWithinBase()

  Caller->>Resolve: resolveSafePath(basePath, inputPath)
  Resolve->>Guards: reject empty base + UNC paths
  Resolve->>Decode: decode repeatedly until stable

  alt decode fails or max iterations exceeded
    Decode-->>Resolve: error
    Resolve-->>Caller: FailedToDecodePathError
  else decoded path
    Resolve->>Guards: reject control chars and null bytes
    Resolve->>Resolve: normalize absolute vs relative input
    alt absolute input already inside base
      Resolve->>Base: isWithinBase(base, input)
      Base-->>Resolve: true
      Resolve-->>Caller: normalized absolute path
    else relative or outside-base input
      Resolve->>Resolve: join input to base and normalize
      Resolve->>Base: isWithinBase(base, resolved)
      alt escaped base
        Base-->>Resolve: false
        Resolve-->>Caller: PathTraversalError
      else inside base
        Base-->>Resolve: true
        Resolve-->>Caller: resolved path
      end
    end
  end
```

### `decodePathSafely()`

```mermaid
sequenceDiagram
  actor Caller
  participant Decode as decodePathSafely()

  Caller->>Decode: decodePathSafely(encodedPath)
  loop until path stops changing
    Decode->>Decode: decodeURIComponent()
    Decode->>Decode: replace %2e, %2f, %5c variants
  end

  alt iterations exceeded
    Decode-->>Caller: MaximumDecodingIterationsExceededError
  else stabilized
    Decode-->>Caller: decoded path
  end
```

### `isWithinBase()`

```mermaid
sequenceDiagram
  actor Caller
  participant Within as isWithinBase()

  Caller->>Within: isWithinBase(base, resolved)
  Within->>Within: trim + normalize inputs
  Within->>Within: apply leading slashes where needed
  Within->>Within: lower-case on case-insensitive platforms
  Within->>Within: compare exact match or base + separator prefix
  Within-->>Caller: boolean
```

## Design Notes

- URL decoding is iterative because traversal attempts may be double-encoded.
- Windows behavior is treated explicitly, including drive handling and unsupported UNC paths.
- `isWithinBase()` avoids partial prefix mistakes like `/root` matching `/root2`.
- This package does lexical path safety only; the Node backend adds real-path symlink checks on top.

## Testing Use

- repeated encoded traversal attempts
- Windows drive and case-sensitivity edge cases
- UNC path rejection
- control-character and null-byte rejection
- absolute input that is already valid vs absolute input that escapes base
